1、docstring说明这段似乎互相矛盾，现在的verifier阶段主要想对env阶段的产物（包括建立的环境、跑出来的轨迹）走一遍：

> ```
> 背景：原方案为每个任务生成一段 verify_task 验证代码，再由独立的 preflight 阶段按探针完成情况拆分任务。
> 改造后不再生成任何验证代码，也不再在本阶段判断任务是否完成——数据库状态本身是唯一事实来源，
> 任务是否完成完全由 RL 阶段的 LLM judge 根据「任务 + 轨迹 + 初始快照 + 精确 diff」判定。
> 
> 本阶段只做两件事：
>   ① 体检：校验 sample / 数据库 / env / 轨迹是否按 (scenario, task_id) 正确对齐，快照是否可用且在体积门槛内；
>   ② 建名单：读 env 阶段保存的 rollout 探针，按「是否走完协议」拆出 solvable / unsolvable，产出 RL 可直接使用的清单。
> ```

2、输出似乎有点混乱：

> ```
> 输出（全部 JSONL，先写临时文件再原子替换）：
>   - output：主审计清单，每行一个 sample 任务，含各项检查结果、淘汰原因、探针摘要
>   - bad_output：不可用任务清单
>   - ready_output：可训练任务清单（task_id 为 RL 使用的 0 基整数）
>   - solvable_output / unsolvable_output：按探针难度拆分的两份清单
> ```
